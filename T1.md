# Тест-план: Получение статуса продукта (API)

**Задача:** Т1  

**Автор:** Беляков Александр

## 1. Введение
Данный документ описывает план тестирования REST API метода для проверки статуса готовности продукта.

### Входные данные
*   **Endpoint:** `/products/{productId}/status`
*   **Auth:** Параметр `authToken` (query) — обязательный, 16 символов (цифры и буквы).
*   **Query Params (опциональные):**
    *   `recalculate` (boolean: true/false/null)
    *   `owner` (string: Создатель/Пользователь/null)
    *   `region` (string: Северо-Запад/Сибирь/Поволжье)

### Ожидаемый результат
*   **Успех (200):** JSON `{ "productStatus": 1 }` (или 0).
*   **Ошибки:** 401 (Auth), 404 (Not Found), 500 (Server Error).

---

## 2. Стратегия тестирования и техники тест-дизайна

Для покрытия функционала используются следующие техники:
1.  **Анализ граничных значений (BVA):** Для проверки длины токена (15, 16, 17 символов).
2.  **Классы эквивалентности (EP):**
    *   Токен: Валидный / Невалидный (спецсимволы, пустой).
    *   ID продукта: Существующий / Несуществующий / Невалидный формат.
3.  **Попарное тестирование (Pairwise):** Для проверки комбинаций опциональных параметров (`recalculate`, `owner`, `region`), так как они не зависимы друг от друга.
