# ТЕСТ ПЛАН

## 1. Идентификатор плана (Test Plan Identifier)
**ID документа:** `TP-API-001`

**Дата:** 12.02.2024

## 2. Введение (Introduction)
Данный план описывает стратегию, ресурсы и график тестирования REST API метода `GET /products/{productId}/status`.
**Цель:** Подтвердить, что функциональность метода соответствует требованиям спецификации (Задача Т1), включая проверку статусов, валидацию токенов и обработку ошибок.
**Область применения:** Интеграционное тестирование API на тестовом окружении (Stage).

## 3. Объекты тестирования (Test Items)
*   **Компонент:** Сервис продуктов (Backend).
*   **Endpoint:** `GET /products/{productId}/status`.
*   **Спецификация:** Задача Т1 (требования к входным/выходным параметрам).
*   **База данных:** Тестовый набор данных с продуктами (статусы 0 и 1).

## 4. Особенности, подлежащие тестированию (Features to be Tested)
1.  **Авторизация:** Проверка валидности `authToken` (длина, состав символов).
2.  **Получение статуса:** Корректный возврат статусов (1 - Готов, 0 - Не готов).
3.  **Обработка параметров:** Корректная обработка опциональных параметров (`recalculate`, `owner`, `region`) и их комбинаций.
4.  **Коды ответов:** Проверка соответствия HTTP-кодов ситуациям (200, 401, 404, 500).
5.  **Формат ответа:** Валидация JSON-схемы.

## 5. Особенности, не подлежащие тестированию (Features not to be Tested)
1.  **Нагрузочное тестирование:** Проверка производительности API под высокой нагрузкой выходит за рамки данной задачи.
2.  **Генерация токена:** Тестируется только валидация токена на входе, а не процесс его создания/выдачи.
3.  **Безопасность (Penetration Testing):** Глубокое сканирование уязвимостей (SQL Injection, XSS) не проводится, только базовые проверки входных данных.
4.  **UI:** Графический интерфейс отсутствует.

## 6. Подход (Approach)
*   **Тип тестирования:** Ручное тестирование API (функциональное, позитивное/негативное).
*   **Методология:** Black Box (Черный ящик).
*   **Техники тест-дизайна:**
    *   Классы эквивалентности (для ID и токенов).
    *   Граничные значения (длина токена 15/16/17).
    *   Попарное тестирование (Pairwise) для опциональных параметров.
*   **Инструменты:** Postman, cURL, Swagger UI.

## 7. Критерии приёмки (Item Pass/Fail Criteria)
**Входные критерии (Entry Criteria):**
*   Билд успешно развернут на тестовом стенде.
*   База данных наполнена тестовыми данными (продукты с ID 100, 101).

**Критерии выхода (Exit Criteria):**
*   100% тест-кейсов с приоритетом `Blocker` и `Critical` пройдены успешно.
*   Общий процент прохождения тестов > 90%.
*   Отсутствуют открытые дефекты критичности Major и выше.

## 8. Критерии приостановки и возобновления (Suspension/Resumption Criteria)
**Приостановка (Stop Testing):**
*   Недоступность тестового стенда (возврат 503/404 на все запросы).
*   Блокирующий дефект авторизации (невозможно выполнить ни один запрос даже с валидным токеном).

**Возобновление (Resumption):**
*   Устранение блокирующей проблемы и успешное прохождение Smoke-теста.

## 9. Результаты тестирования (Test Deliverables)
По итогам тестирования предоставляются:
1.  Данный Тест-план.
2.  Набор Тест-кейсов (см. Раздел 14).
3.  Отчет о дефектах (Bug Reports) в баг-трекере.
4.  Итоговый отчет о тестировании (Test Summary Report).
